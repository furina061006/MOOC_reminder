## 未发布

> **验证状态（2026-09-21 用户实测）**：标 ✅ 的条目已在真实浏览器里确认生效（清除数据后刷新可恢复、
> 课程页挂后台也能抓到、作业跳转目标完全正确）。其余条目目前只有代码与单测覆盖，尚未在浏览器逐项验证。
> 「同一课程页面只抓取一次」是 30 分钟节流的设计行为，本次未改动，见 `backlog.md`。

- ✅ **修复「某门课不切到它的页面就抓不到」**：浏览器会冻结、甚至卸载长期挂在后台的标签页，这种页面里已经没有插件的代码了——既不能上报「我是哪门课」，也不能接手抓取。以前插件挑到这样一个页面时会白等 90 秒并把整次刷新判为失败（所以有时候刷新没反应、过一会儿又好了），而且只要列表里还有别的课，就再也不会去问那些页面。现在每次刷新都会先问一遍**所有已打开的课程页**：能回答的页面会顺手重新登记自己的课程，抓取也只会交给刚刚回答过、确实活着的页面；一个能回答的都没有时，插件会用一个临时的后台页面把作业抓下来。
- ✅ **修复「清除数据后再刷新，一条都抓不到」**：以前「清除数据 / 删除课程」之后，插件只会向已经打开的页面索要课程**链接**，而课程学习页上根本没有这类链接（左侧菜单用的是菜单项 ID，不是链接），于是课程列表永远恢复不了，只能重新打开页面。现在课程页会自己上报身份，插件也会顺带询问所有已打开的 icourse163 页面（「我的课程」页里的链接最全），刷新即可自动恢复。注意：这样只能恢复**当时打开着的**课程页；没打开的课程仍需打开一次「我的课程」页才会回来。
- ✅ **修复刷新时「卡住且什么都不说」**：向某个已打开页面要数据时，如果那个页面被浏览器冻结（长时间留在后台），请求会永远等不到回应，整个刷新就静默卡死、日志停在半句。现在每个页面最多等 1.5 秒，逐页报告有没有回应，某一页不回应不再影响其余页面。
- ✅ **清空数据后不再需要手动刷新页面**：以前「清除数据 / 删除课程」后，已经打开着的课程页不会重新上报，插件就一直抓不到任何东西。现在插件会主动让已打开的课程页重新扫描一次，自动恢复。
- **抓取失败时不再「静默无反应」**：当没有任何已载入课程（或全部被忽略）时，刷新会直接结束且不留下任何说明，导致 popup 空白却没有原因。现在会在设置页「错误报告」和 popup 提示里写明具体原因。
- **新增「已追踪课程」管理**：设置页可以看到自己追踪的课程列表（含每门课「未完成 / 共几条」），并可以「忽略」（停止追踪——不再抓取、不计入徽章与提醒，随时可恢复）或「删除」（清掉该课程及其全部作业记录）。
- **修复「开了多个课程页面却抓取不到」**：以前刷新只发给最近打开的那一个学习页，而若它是在扩展重载之前打开的（页面里没有 content script），整个抓取会直接失败，popup 还会误提示「请先登录 MOOC 并至少打开过一门课程」。现在会依次尝试各个学习页，全都不行时改用临时代理页兜底；失败时也会照实显示真实原因。
- **修复 SPOC 课程「老师新增的内容」抓不到**：老师在自己课上新增的分组（如「线上学习任务」「反转课堂/翻转课堂」）现在会正常出现在列表里。此前插件只抓了课程的一个学期（源课程），而老师新增的内容存在另一个学期里，于是整组消失。已在真实课程数据上验证：原来只抓到 1 条，现在完整抓到 5 条（老师 4 条 + 源课程 1 条）。
- **修复可能出现的重复作业**：作业节点自带的元数据里也含名称，过去会被当成第二个作业读进来（只因为名字相同才被去重逻辑掩盖）。现在不会再多读出重复项。
- **新增「更新提醒」**：后台默认每 12 小时检查一次 GitHub 上的新版本；发现新版本时弹出一次系统通知（同一版本不会反复打扰），设置页新增「更新」区块显示当前版本、最新版本、上次检查时间，并提供「检查更新」与「前往下载」按钮——点击通知或按钮会直接打开新版的 ZIP 下载链接。
- **新增「自动检查更新」开关（默认开）**：关闭后插件不会发出任何外部请求，「检查更新」按钮仍可手动使用。检查只向 GitHub 发一个请求，不含任何作业或账号数据。
- **安装方式改为从 Releases 下载**：README 的安装步骤现在指向 Releases 的 `mooc-reminder-v*.zip`，解压后即为可直接加载的扩展目录。
- ✅ **修复 SPOC 条目跳转错误路由（这一次真正生效）**：点击 SPOC 作业会打开正确的 `/spoc/learn/` 页面，并带上正确的 `?tid=` 路由 ID（此前可能用的是 API ID）。2026-09-18 曾记录过一次「已修复」，但那次只改了运行时并不执行的代码副本，实际点击仍会跳到同名普通 MOOC 课程页。2026-09-21 用户实测确认：MOOC 与 SPOC 的作业跳转目标都完全正确。
- **修复 SPOC 课程标题被改成 MOOC 名称**：同名普通 MOOC 的课程链接不再覆盖 SPOC 课程的标题与类型，已确认是 SPOC 的课程不再被降级。
- **升级后请打开一次 SPOC 学习页**：旧作业条目需要借这次访问记录真实课程地址，之后点击即可正确跳转。
- **修复「清理已完成」不持久**：清理后的已完成作业会被记住，后续 API 同步不会再把它们重新写回列表；如果该作业确实重新变为未完成（例如新一轮作答），仍会正常显示。
- **修复手动提醒在同名课程下互相冲突**：手动提醒的唯一 ID 现在包含课程，两门课程即使显示名相同、标题和截止时间也相同，也能各自独立管理。
- **修复课程元数据并发丢失**：课程列表的读写改为串行化，课程发现、SPOC 真实 termId 更新和 API 同步同时发生时不再互相覆盖，避免漏课或 termId 回退。

## 2026-09-04

- **无标签页自动刷新**：已载入普通 MOOC 或 SPOC 课程后，没有现成学习标签页时会创建一个非激活临时代理页，复用 Content Script 批量抓取；完成、超时、关闭或重启后仅清理该临时页。
- **低频后台检查**：后台检查和徽章刷新设置改为小时单位，默认均为 12 小时；打开课程页和浏览器启动仍会触发事件驱动同步。
- **每日摘要补发**：当天首次启动浏览器时，若尚未发送摘要，会立即尝试推送 48 小时内截止或已过期的作业摘要；免打扰时段则在结束后补发。
- **摘要文案调整**：设置页说明改为“每天定时”，不再限定早上。

## 2026-08-16

- **修复「稍后提醒」失效**：snooze 现在会同时清除已通知档位记忆，24h 后同档位会正常再次提醒（此前对已过期条目点一次稍后提醒就永远不再提醒）。

## 2026-06-28

- **contentType 优先于名字正则**：提取匹配条件改为以 API `contentType`（2=quiz, 3=homework, 6=exam）为主，名字正则仅当 `contentType` 空缺时启用，防止“期末考试”因名字含“测试”被误提取。
- **node.test 统一后备**：所有信号/完成判定字段同时查顶层和 `node.test` 子对象（部分 SPOC 课程字段在 test 内），顶层优先，原值不受影响。
- **完成判定定型**：`score > 0`（有成绩） || `submitted && !inPeerReview`（已提交且互评未卡住）|| `hasCompletedText`（文本标记）；`submitted` 同时认 type:3 和 type:6。
- **考试标签改为手动确认**：考试在 popup 中显示琥珀色「手动确认」标签，完成逻辑不变。
- **SPOC bridge 支持 termDto**：部分 SPOC 课程（如军事理论）使用 `window.termDto.id` 而非 `moocTermDto.id`。
- **SPOC 跨课程污染修复**：`data-mooc-real-termid` 仅在本课程页面时才用于替换 termId。
- **后台刷新用 activeTermId**：`apiRefreshCourse` 使用 `course.activeTermId || course.termId`。
- **Course_UPDATE 携带 courseName**：SPOC 课程名称持久化，修复「未知课程」问题。
- **SPOC 互评作业修复**：`apiDetectPhase` 添加 `node.contentType` 后备（SPOC 数据无 `node.type` 和 `node.test`，类型标识在 `contentType`）。
- **`scorePubStatus:1` 时间检查**：不再看到 1 就直接判定完成，改为先验证 `evaluateEnd` 是否真正到期；到期才判完成，未到期按时间正常判断互评阶段。
- **移除冗余 `scorePubStatus===0` 门控**：`inPeerReview` 和 `phaseDeadline` 中额外检查 `scorePubStatus===0` 导致 `apiDetectPhase` 正确返回 `peerreview` 后被否决，现已移除，直接信任相位检测。
- **`.claude/logs/` 纳入版本管理**：开发日志解除 gitignore，供其他开发者追踪技术决策。
