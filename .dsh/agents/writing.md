# 文档写法（Markdown 技巧与仓库文案约定）

> 入口索引与工作约定在仓库根目录 [`AGENTS.md`](../../AGENTS.md)；本文件是 `.dsh/agents/` 知识库的一部分。

**这里放「怎么写」**：所有仓库内 Markdown 的格式技巧与文案约定。**这类细节不要在 `AGENTS.md` 里展开**——它在每轮上下文里，只放索引 + 红线 + 路由表。以后遇到新的写法坑，加到这里，别加回索引。

## 加粗不要写成 `**「x」**`

`**` 紧贴前面的文字、右边紧跟 `「`（标点）时，按 CommonMark 的 flanking 规则**开不了强调**，预览里会原样显示 `**`：

| 写法 | 结果 |
| --- | --- |
| `点一下**「重新加载」**` | ❌ 显示字面 `**`（前面 `下` 是文字、右边 `「` 是标点，开标记只满足 right-flanking） |
| `点一下「**重新加载**」` | ✅ 加粗 |
| `**「重新加载」**` 出现在行首或空格 / 标点之后 | ✅ 能加粗，但为统一仍建议写成上一种 |

**规则**：加粗范围正好是引号里的文字就用 `「**x**」`；整句加粗就用 `**整句**`。**不要把 `**` 夹在文字与 `「` 之间。**

**自查**：`npm run validate` 查不出这类问题（没有测试守着）。可疑点是 `**「` 前面紧贴文字、或 `」**` 后面紧跟文字；准确判定要按 flanking 规则配对 `**`（列表项 / 表格行 / 标题各自成块，行内代码按「文字」占位），2026-09-23 用的检查脚本与结论见 [`.dsh/logs/2026-09-23-backlog-cleanup-and-popup-timing.md`](../logs/2026-09-23-backlog-cleanup-and-popup-timing.md)。

## 历史日志是存档，不改写正文

`.dsh/logs/` 下的日期日志是**当时的过程快照**。发现旧日志写错了、过时了，**不要改它的正文**——在当天的日志或新日志里说明即可；改名 / 搬目录这类结构性变更用 `git mv` 保留历史（2026-09-21 的 `.claude/` → `.dsh/` 就是这么做的）。

结论变化的分工：**面向用户**的写 `.dsh/logs/changelog.md`；**现行事实**写 `.dsh/agents/`；**过程与根因**留 `.dsh/logs/`。

## 其他既有约定（细则在各自文档）

- **行内代码**（反引号）用于路径、键名、命令、字段名：`homework_items`、`npm run validate`、`.dsh/agents/`。
- **README 的仓库链接必须是绝对 URL**：README 会进发布 zip，而 zip 里没有 `docs/`、`.dsh/`、`CONTRIBUTING.md`，相对链接会变死链——由 `tests/unit/repo-hygiene.test.mjs` 守着。
- 文档分工（哪份文档放什么）见 [`AGENTS.md`](../../AGENTS.md) 的「知识管理约定」；面向用户的文案与发版说明见 [`operations.md`](operations.md)。
