# 2026-09-21 — 开发日志索引：生成式 + CI 校验

## 起因

用户问：**「日志目录索引这个其实可以有，就是后期维护会不会太麻烦？」**

背景：当天早些时候我曾加过一版 `.dsh/logs/` 的 README 索引，用户当场否掉（见 `2026-09-21-day-summary.md`
「走过的死路与被否决的方案」第 2 条）。但那次否掉之后，用户重新考虑了一下，问题不在于「要不要索引」，
而在于**维护成本**。

## 先摆事实，再选形态

```
22 篇日志 / 22 篇都有规范的首行 `# 标题`
新增频率：早期每月几篇；大改动日一天 5 篇（2026-09-21）
标题本身就是好的一句话摘要，例如「SPOC「老师新增内容」抓不到 — 根因与修复」
```

关键判断：**主题信息本来就已经存在于日志里**（每篇的 H1），所以索引不该要求任何人重新写作。
于是「维护麻不麻烦」完全取决于索引是哪种形态：

| 形态 | 每篇的额外成本 | 腐烂风险 |
| --- | --- | --- |
| 手写散文式索引（当天被否掉的那版） | 重新读日志、提炼、归类、改表格 —— 几分钟 | 高，漏一次就过期，且过期平时看不出来 |
| **生成式索引（本次采用）** | 跑一条 `npm run logs:index` | 零 —— 测试断言「提交的索引 == 重新生成的结果」 |
| 手写一行 + 只查存在性 | 15 秒补一行 | 中，标题改了索引不改，内容会脱节 |

用户在三个选项里选了生成式。

## 做了什么

### 1. `tools/gen-log-index.mjs` —— 索引完全由日志派生

- **主题 = 各日志首行的 `# 标题`**。没有 H1 的日志直接报错：主题只能来自日志自己，不让它静默无名。
- **去掉标题里冗余的日期**（日期已有独立列）：`2026-09-21 — 「清除数据后…」` → `「清除数据后…」`；
  但**中间**出现的日期保留（`backlog 2026-09-01 审查问题的修复` 说的是历史日期，不是本篇日期）。
- 月份分组、新的在前、**同一天按文件名稳定排序**（保证比对可复现）、表格里的 `|` 转义。
- **非日期文件必须在 `STANDING_DOCS` 登记**（`changelog.md`、`architecture.md`），否则报错 ——
  免得某天多了个 `notes.md`，它既不在索引里、也没人发现。
- 导出纯函数 `renderIndex(repoRoot)`：测试直接调它比对，不必起子进程；CLI 入口有守卫，
  被 `import` 时不会写盘。`--check` 只校验不改文件（人肉自查用）。

### 2. 接进 `npm run validate`：索引不可能悄悄过期

`tests/unit/repo-hygiene.test.mjs` 新增第 3 条不变量：**逐字节**比对 `.dsh/logs/README.md` 与
`renderIndex(root)`，再顺手确认每篇日期日志都出现在索引里（防生成器因命名/正则变化漏扫）。
两种典型的腐烂——「忘了跑生成器」和「有人直接手改」——都会当场失败，修法只有跑 `npm run logs:index`。

### 3. 文档接线

- `package.json`：`npm run logs:index`
- `AGENTS.md`：路由表那条「想知道为什么这么改」改指索引；知识管理约定里注明 `README.md` 是生成物；
  相关文档列出索引
- `.dsh/agents/operations.md`：开发命令加一条；仓库卫生补上「索引是生成的」这个事实与它的守门方式
- `CONTRIBUTING.md`：提交前命令、仓库结构树、约定各补一处

## 为什么不选「手写一行 + 只查存在性」

15 秒补一行确实也能接受，但测试只能保证「没漏」，保证不了「对」：日志标题改了、索引那一行没人改，
两者就悄悄分叉。逐字节比对把这个坑一起堵掉，代价是作者必须跑一条命令 —— 而且忘了跑会被 CI 明确告知，
不是靠自觉。

## 验证

- **负向**：手工往 `.dsh/logs/README.md` 追加一行 → `日志索引是生成物…` 这条 `not ok`；恢复后 `pass 7 / fail 0`
- **负向**：新建日志后不跑生成器 → `node tools/gen-log-index.mjs --check` 退出码 1
- **负向**：日志没有 `# 标题` → 抛错退出 1；出现未登记的非日期文件 → 抛错退出 1
- `npm run validate`（eslint 0 error；全部单测通过，含新增的那条）

## 已知取舍

- 旧日志里有 3 篇标题很泛（`2026-06-24` / `2026-06-26` 都叫「开发记录」，`2026-06-27` 是「Development Log」），
  在索引里只能显示成「开发记录」。改标题等于重写历史存档，按约定**不动**；要去掉这个含糊得单独决定。
- 常设文档的一句话说明写在生成器的 `STANDING_DOCS` 里（每个文件一行），不是从文档正文抽的 ——
  这类文档变化极少（历史上就 2 个），换来的是说明可以比 H1 更准确（例如点明 `architecture.md` 是历史存档）。
